# MotoNav iOS 0.15.3

专辑封面「张冠李戴」修复版。固件无需更新（任意支持 bulk type 5 的版本均可）。

## 0.15.2 的问题

0.15.2 已经能把封面推上圆屏，但显示的不是当前歌曲的封面。实测：

- 网易云音乐会往 AMS 的 **Title 字段**塞歌词或提示语，例如「作曲: Anthony Gonzalez」「纯音乐，请欣赏」；
- 用这类字符串搜 iTunes，结果分别是 "Wait (feat. Emile Parisien…)" 和「大波浪 / 百因必有果 (DJ版)」等完全无关的曲目；
- 0.15.2 的「匹配不上就取第一张可用封面」兜底，把这些不相干的封面直接推上了圆屏。

## 修复

- **改用干净的专辑名**：固件本来就完整转发了 AMS Track 的 `Artist / Album / Title`（`AppleMediaData.h` 字段映射 2/0/1），`MusicBridge.publish` 现在把 `metadata.album` 一并交给封面查询，优先用 `entity=album` 搜专辑名，直接拿专辑封面。
- **拒绝脏歌名**：Title 里出现「作曲 / 作词 / 编曲 / 纯音乐 / 请欣赏 / 歌词 / 暂无歌词」等关键词、超过 32 字、或含中文逗号顿号时，判定为歌词/提示语，不参与搜索。
- **删掉凑数兜底**：只接受可靠匹配（完全同名 20 分、包含 10 分、被包含 8 分，另加歌手加分），低于 8 分一律不发送，保持当前封面；再也不会把搜索结果第一张硬塞给圆屏。
- **去重更稳**：用专辑名而非歌词做去重键，歌词每几秒刷新也不会反复发起网络查询。
- **排序更准**：完全同名优先；同分选名称更短的，避开 "Remixes & B-Sides" / "Vol. 2" 之类衍生版。
- **新增封面来源**：尝试读取系统正在播放媒体的 artwork（`MPNowPlayingInfoCenter`），若系统允许跨 App 读取，这是最精确的一张；其次是 Apple Music 本地封面，最后才走 iTunes。
- 调试信息里的「专辑封面」状态会显示实际采用的搜索词和结果，例如 `专辑名(us) ✓ 已发送 78 KB [Saturdays = Youth]` 或 `歌名是歌词/提示语，跳过查询 [纯音乐，请欣赏]`。

## 说明

- 若某首歌在 iTunes 各区都没有可靠匹配，圆屏会保持上一张封面或内置黑胶占位图，这是刻意设计：宁缺毋滥。
- 高德 Key 不内置，首次打开在「Key 设置」里填自己的 Key。
- 未签名 IPA，用 Sideloadly + 自己的 Apple ID 签名安装，免费账号 7 天过期；升级可直接覆盖 0.15.0 / 0.15.2。
